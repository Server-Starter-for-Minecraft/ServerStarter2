# テストについて

ServerStarter2 ではテストライブラリとして vitest を採用している

https://vitest.dev

記法については公式リファレンスを参考にすること。

簡単な例は `./example.test.ts`/`./inSourceExample.ts` に記述した。

テストに関する設定は`vitest.config.js`にある。

# テストの実行

`bun run test`ですべてのテストを実行できます。

| コマンド               | 内容                                                                             |
| ---------------------- | -------------------------------------------------------------------------------- |
| `bun run test`         | すべてのテストを実行(ウォッチモード)                                             |
| `bun run test:offline` | `network`タグ以外のテストを，外部への通信を遮断して実行(PR の必須 CI と同じ条件) |
| `bun run test:network` | `network`タグのテストのみを実行                                                  |

※ `test:offline`は環境変数の指定に Bun Shell の記法を使うため，必ず`bun run`経由で実行すること

# 外部サービスに依存するテスト (`network`タグ)

Mojang・PaperMC・Forge 等の外部サービスに実際にアクセスするテストには`network`タグを付ける。

```ts
test('バージョン一覧を取得できる', { tags: ['network'] }, async () => { ... });
describe('papermc version', { tags: ['network'] }, async () => { ... });
```

- `network`タグのテストはタイムアウトが 60 秒になり，失敗時は 10 秒おきに最大 2 回再試行される(`vitest.config.js`)
- `network`タグが無いテストは，CI では外部への通信を遮断して実行される(`test/setup/blockNetwork.ts`)。
  タグを付け忘れた場合は「たまに落ちる」のではなく「必ず落ちる」ため，すぐに気付ける
- `describe`の直下(テストの収集時)で外部サービスにアクセスしないこと。
  収集時の失敗は再試行されず，タグで除外した実行でも収集処理は走るため，通信は`test`の中で行う

### 外部サービスに依存させない書き方

テストの目的が「外部 API との連携」ではなく「アプリ側のロジック」である場合は，外部サービスに依存させない。

- URL からの取得処理そのものを試す場合は，ローカル HTTP サーバー(`test/util/localServer.ts`)を使う
- Mojang の配布 API(バージョン一覧・各バージョンの詳細 JSON)は，
  `src-electron/source/version/test/fromURLMock.fixtures.ts`の`createFromURLMock`で固定レスポンスを返す
  (外部 API との連携そのものを確認するテストのみ，`network`タグを付けて本来の`BytesData.fromURL`を`fallback`に渡す)

# CI での扱い

| ワークフロー › ジョブ                        | 実行タイミング | 対象              | 失敗したときの見方                                           |
| -------------------------------------------- | -------------- | ----------------- | ------------------------------------------------------------ |
| `Vitest` › `vitest`                          | PR             | `network`タグ以外 | 外部サービスに依存しないため，コードの問題とみなして修正する |
| `Vitest` › `vitest-network / vitest-network` | PR             | `network`タグのみ | 下記を参照                                                   |
| `Vitest (network)` › `vitest-network`        | 毎週月曜・手動 | `network`タグのみ | 下記を参照                                                   |

PR では`Vitest`ワークフローの`coverage-report`ジョブで両者のカバレッジを合算して PR にコメントする
(`network`タグのテストでしか通らない処理もカバレッジに含めるため)。
`network`タグのテストが外部サービスの障害で失敗した場合も，取得できた分で合算する。

`network`タグのテストのジョブは，テスト単位で再試行した上でなお失敗した場合に赤くなる。

1. ログでどの外部サービスへのアクセスが失敗したかを確認する
2. 通信エラー(`fetch failed` / `ETIMEDOUT` / 5xx など)の場合は，外部サービスの一時的な障害の可能性が高い。
   時間をおいてワークフローを再実行し，通れば対応不要
3. 再実行しても同じテストが失敗し続ける場合や，レスポンスの形式・値に関するアサーションで失敗している場合は，
   外部 API の仕様変更などが疑われるため，アプリ側の修正を検討する

# テストの配置

### ユニットテスト

本プロジェクトでは In Source Testing を採用し、ユニットテストは実装と同じファイル内に記載する。

`src-electron/util/zip.ts`に例があるので参考まで。

`.ts`内で`test`と打つと In Source Testing のスニペットが出るので活用してください。

### その他とテスト

個別でテストファイルを配置する場合はファイル名を `**/*.test.ts`とすること。

本ディレクトリはそれ以上の結合テストやモックの実装を書く。
